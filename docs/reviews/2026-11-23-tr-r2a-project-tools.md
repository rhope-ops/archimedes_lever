# Tool retirement research, step R2a: project-specific tools of 5 repos

Read-only inventory (2026-11-23). Source: local clones of the five repos; nothing in them was changed. No retire, shrink or keep decision is made here: the last column lists candidate standard tools only, with trade-offs.

## How the numbers were made

- Tool = a script or program the repo owns (py, sh, ps1, mjs, js) that is not named in the repo's `.check.lock`. Kit-locked files are excluded. Files named in `.check.lock` are matched by exact path.
- Test files (test_*.py, *_test.py, *.test.mjs, tests/, site/tests/) are not rows: they are named in the Test column and totalled in one line per repo. Product code is a separate line per repo.
- Workflow files that are not kit-locked are listed as rows marked (workflow); they are counted apart from scripts.
- Lines = `wc -l` equivalent (newline count). Commits = `git log --since=2026-10-24 --oneline -- <path> | wc -l` (clones of RADE, 90-161.Z, 33-332.Z, sec-source hold about 40 days; icf-source holds full history; all counts are a 30-day window).
- Callers = files that name the script (path or module import): check scripts, workflows, package.json, other tools and product code. `*name` marks a kit-locked caller. Names are base names. Up to 4 shown. Test column: a test file named for the script, else a test file that names it, else `built-in --test` when the script has a self-test flag, else `none`. Job text is the first sentence of the script header (parentheticals dropped).
- The caller and test columns are text matches, not call proofs; a script named only in a comment still shows. A tool run by hand shows `none`.
