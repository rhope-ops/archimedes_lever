# Kit changelog

One line for each kit version that a project must take by a sync (`scripts/sync_baseline.py`, run from the project). The version is the date of the change (`KIT_VERSION`); a project's `.check.lock` records the version it has. Why each change was made: [DECISIONS.md](DECISIONS.md).

| Version | Change | A project must |
|---|---|---|
| 2026.11.20.1 | Every project takes kit changes by sync, and its own code lives in its own files. Two extension points: `scripts/check_content_local.py` (a project's own finders for the content check) and `scripts/code_standard_gate.py` (its own stricter code-standard rules; the settings `code-max-line-chars` and `code-c1-safety: strict` are for it); a file that cannot be loaded fails its check, and `scripts/check.sh` runs each file's `--test`. The kit files a project gets meet the strict code standard (three safety label lines, full docs per function, lines of at most 200 characters); for that, parts moved into new modules: `scripts/check_content_finders.py`, `check_content_test_local.py`, `check_settings_test.py`, `code_standard_parse.py`, `bloat_check_rules.py`. `check_settings.py --migrate` no longer stops on an old key that has no place in the layout (one `NOTE  dropped` line each) and replaces an old kit header line at the top of `.check`. A sync replaces an agent file or docs/FIRST_USE.md that is an earlier kit version, and names one the project tuned. The duplicate count skips marked generated blocks. The workflow pins the checkout action by commit and stores no credentials. | Sync. A project with its own scanner or code-standard code in a kit file: first move it into the two extension files (`.claude/skills/port/SKILL.md`). Run `python3 scripts/check_settings.py --migrate` again if it stopped before, or if `.check` still starts with the old header line. Read the lines the sync prints for docs/FIRST_USE.md and the agent files. |
| 2026.11.20 | Found by the first pilot sync: the agent files `scout`, `worker` and `reviewer` are kit files (replaced by a sync and locked; an old copy restated a hard rule). In a synced project, the rule conflict check covers only changed "Project rules" lines; the kit checks its own rule text. | Sync. A project that tuned a kit agent file moves that text to an agent with its own name first. |
| 2026.11.19 | Two rule tiers in AGENTS.md: "Hard rules" (nothing relaxes them) and "Defaults" (the method is the agent's unless the task states it), each rule with a bold label; 28 rule bullets, from 35. Merge by lane: A (docs that are not rules) and B (code, after a clean fresh review) merge without a question; C (instruction and guard files, live effects, data writes, security) asks the owner. Layered sync: kit files and kit rule text are locked, a project adds to a kit skill in `.claude/skills/<name>/PROJECT.md`, and a kit release arrives as one pull request (skill `kit-update`, was `port`). Skills `run-verify` and `ui-verify` are one skill, `verify`. Caps: session load 5,000 tokens (warning at 4,500). The pre-push hook refuses a commit whose author or committer address is not a noreply address. | Sync. Before it: move project text out of kit sections and kit skills into "Project rules", `scripts/check.local.sh`, `.check` or a PROJECT.md (the dry-run diff shows it). After it: delete the files the sync lists as moved (`run-verify`, `ui-verify`, `port`), and remove a "No kit sync" project rule with the owner's approval. |
| 2026.11.18 | One `check`: the personal-data guard is the content check of `scripts/check.sh` (`scripts/check_content*.py`, settings file `.check`, `block:` lines, the owner's terms list, the hook also on Write, Edit and outgoing Bash). Caps: AGENTS.md 200 lines and a session load of 6,000 tokens. One home per rule. Pull-request merge rule. Kit lock `.check.lock`. One config layout: `.check` (every setting a person edits, now also the `code-` and `audit-` lines), `.check.lock`, and `.check.state.json` (what tools write: the code standard debt, the last audit, the time baselines); `.code-standard.json` and `.bloat-audit.json` are replaced. | Sync; run `python3 scripts/check_settings.py --migrate` (it renames `.pii-guard` to `.check`, moves the settings of `.code-standard.json` and `.bloat-audit.json` into `.check` and their state into `.check.state.json`, and deletes the old files); delete `scripts/pii_guard*.py` and `.github/workflows/pii-guard.yml`; optional: add the `CHECK_TERMS` secret. |
