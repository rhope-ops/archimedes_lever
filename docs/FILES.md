# Kit files

Every file in the archimedes_lever kit and what it does. Kit only: `scripts/bootstrap.sh` deletes this file, because a project gets its own README.

| File | What it does |
|---|---|
| AGENTS.md | Rules for every agent, at most 35 bullets; procedures live in the skills. Project rules go at the end (at most 15). `scripts/bloat_check.py --rules` checks both caps. |
| CLAUDE.md | One line that imports AGENTS.md, because Claude Code reads CLAUDE.md. |
| docs/NEXT_PROMPT.md | Short handoff: where things stand, open work, and what needs the owner. |
| docs/DECISIONS.md | The maintainer's own decisions. Public. A record that agents read on demand, not at start, and not a rule set: a decision that must bind every session is a line in AGENTS.md "Project rules". A project gets the blank copy from docs/templates/ instead. |
| docs/templates/ | Blank DECISIONS.md and LOG.md for a new project. Bootstrap moves them into docs/ and deletes this folder; sync uses the LOG.md copy. |
| .claude/skills/ | Claude Code skills, synced to projects. Each holds a procedure that only some tasks need, so its text loads only then; AGENTS.md names each file, so a host without skills can read it. `deliver` (commit, push, merge; the two check lanes; the review gate; branch clean-up), `rule-change` (where a rule belongs, the Suggest format, what counts as approval, the caps), `personal-data` (the guard: state, a blocked push, the denylist), `data-change` (dry run, approval and counts for data writes and large queries), `run-verify` (start the app from the commands in AGENTS.md and prove a change by what it does), `ui-verify` (measure.mjs: screenshots at 375 and 1440 px, light and dark, contrast, targets, overflow), `handoff` (docs/NEXT_PROMPT.md, the resume prompt, start from a handoff) and `port` (bring one kit change to a project by hand; sync or port). Full only: `delegate` (roles, Claude model by tier, fallbacks for claude.ai chat, briefs, review and merge, lanes), `audit` (the periodic bloat, drift, rule and speed audit), `efficiency` (a run slower than its baseline: confirm, find the cause, fix, record) and `project-log` (how to write a project log row). |
| docs/WORKING_WITH_AGENTS.md | For people new to agents: the working loop, clean context, how to ask, what to check. |
| docs/LOG.md | The kit's own public log (the owner, 2026-11-13). In a project (full only): the project log for a timeline and a story deck, from docs/templates/LOG.md: milestones, breakthroughs, misses and decisions, grouped into arcs. A public project keeps its log in a private place named in Project rules. |
| docs/host-prompts.md | Short pointer text for a claude.ai Project. |
| docs/FILES.md | This list. Kit only: bootstrap deletes it. |
| docs/reviews/ | Detailed evidence. Bootstrap deletes the kit's own reports, so a project starts with only docs/reviews/README.md. |
| .bloat-audit.json | The kit's own audit state and timing baselines (scripts/bloat_check.py). Template repo only: bootstrap deletes it, and a project's first audit creates its own. |
| PREFERENCES.md | The maintainer's current Claude account preferences as a template to fill in and paste, with the reason for each rule. Template repo only: bootstrap deletes it. |
| docs/account-skills/ | Account skills that PREFERENCES.md points to (the owner uploads them at claude.ai): `turn-summary`. Template repo only. |
| LICENSE | The kit's license (MIT). Bootstrap moves it to docs/archimedes_lever-LICENSE.txt; each project picks its own LICENSE. |
| .claude/settings.json | Claude Code deny list (force-push including --force-with-lease, `--no-verify`, changing core.hooksPath, hard reset, clean, stash, restore, `branch -D`, reading .env and key files), an allow list of the kit's own commands with an ask list (`--output`, `--record`), a sandbox with a network allowlist (GitHub, PyPI, npm), the Stop hook and the PreToolUse personal-data hook (`pii_guard.py --hook`) for outgoing tool calls. Applies to Claude Code only. |
| .claude/rule-tests.md | Full only. 20 scenarios that check whether an agent follows the written rules in AGENTS.md (hooks check the rest). Run a scenario after a change to its rule; all after a new Claude model family. Its "Section" column tells the rule lint which AGENTS.md sections have a scenario. |
| scripts/bloat_check.py | Full only. Quick measurements at each check-in: start-up reading size in tokens, rule counts against their caps, duplicate lines, big files, audit due date. `--skills` (run by check.sh) checks each skill's frontmatter and trigger text. `--rules` (run by check.sh) fails when a rule cap is passed or AGENTS.md names a path that does not exist, lists each rule line added or removed against origin/main, lints those lines, and with `--gate` (the full lane) fails until a fresh-context conflict check of them is recorded in docs/reviews/. `--lint` lints every rule (near-duplicate, vague, untested). `--time` runs timed operations and `--compare` takes times that a script measured; both compare with the baseline (warn only). Settings and state: `.bloat-audit.json`. `--test`. |
| .claude/agents/ | Claude Code roles: `reviewer` (the author's tier, read-only); full only: `scout` (fast tier, read-only), `worker` (standard). |
| .github/workflows/pii-guard.yml | Pull-request and manual check: `scripts/check.sh`, then the guard on all files and the pull request's commits. Never runs on push (to save Actions minutes). |
| .pii-guard | Turns the guard on; lists allowed exact strings and `skip:` paths. Only the owner edits it. |
| docs/FIRST_USE.md | The first-use questions and what the agent does with the answers. |
| scripts/first_use_check.py | Session-start check (Claude Code SessionStart hook): says KIT in the kit itself (a plain clone), FIRST USE when placeholders remain, and DENYLIST when the guard is on and the session has no name list. `--test`. |
| .gitignore | Keeps .env files and CLAUDE.local.md out of git. |
| scripts/check.sh | The one check command (AGENTS.md "Commands": Test), in two lanes: full (everything) and `--fast` (self-tests only of changed scripts; `check.local.sh --fast`). Checks run in parallel; a `TIME` line gives the wall time and the 3 slowest checks, and the next line compares the times with their baselines (`--record` stores new ones). Runs `scripts/check.local.sh` if it exists; otherwise prints SKIP for project checks. |
| scripts/session_checkin.sh | Start and end check: branch, ahead/behind, uncommitted files, rule counts, and the time and slowest checks of the last check run; compares its own time with its baseline. Installs scripts/git-hooks as an absolute path (so a push from another folder finds the hook) when no other hooks path is set, and repairs the old relative path or a moved clone. `--test`. |
| scripts/git-hooks/pre-push | For Claude, any git client and people: blocks force-pushes, non-fast-forward pushes, deleting main or master, and a push that git runs outside the repo's own work tree (`git --git-dir=... push` from another folder); runs scripts/check.sh (the full lane for a push to main or master, the fast lane for other branches), and pii_guard.py on the tracked files and the pushed commits when `.pii-guard` exists. `--test`. |
| scripts/pii_guard.py | Personal-data and secret guard (`--all`, `--range A..B`, `--push`, files (a path it cannot read fails), `--stdin`, `--hook` (Claude Code PreToolUse: outgoing tool calls); `--require-denylist`; `--status`). `--test`. |
| scripts/stop_check.py | Claude Code Stop hook: stops a turn from ending while work is uncommitted or unpushed. `--test`. |
| scripts/worker_guard.py | PreToolUse hook that limits what `worker` and `reviewer` may do in git. `--test`. |
| scripts/log_check.py | Full only. Checks docs/LOG.md against the project log rules. `--test`. |
| scripts/timeline.py | Full only. Turns one or more project logs into a single self-contained HTML timeline, or a Markdown story outline per arc for a deck (`--outline FILE`). `--test`. |
| scripts/drift.py | Kit only. Reports how a project differs from this kit; changes nothing. `--project DIR`, `--owner NAME`, `--test`. |
| scripts/sync_baseline.py | Kit only. Brings an existing project up to the current kit. Dry run by default; `--apply` writes. Keeps Project rules, Commands and docs/. `--tier full` adds the advanced parts to a starter project. Holds the `ADVANCED_FILES` list. |
| scripts/bootstrap.sh | Fills in the placeholders once, then deletes itself. |
