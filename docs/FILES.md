# Kit files

Every file in the archimedes_lever kit and what it does. Kit only: `scripts/bootstrap.sh` deletes this file, because a project gets its own README.

| File | What it does |
|---|---|
| AGENTS.md | Rules for every agent in two tiers, "Hard rules" (nothing relaxes them) and "Defaults" (the method is the agent's unless the task states it), at most 28 bullets; procedures live in the skills. Project rules go at the end (at most 15). `scripts/bloat_check.py --rules` checks both caps. |
| CLAUDE.md | One line that imports AGENTS.md, because Claude Code reads CLAUDE.md. |
| docs/NEXT_PROMPT.md | Short handoff: where things stand, open work, and what needs the owner. |
| docs/DECISIONS.md | The maintainer's own decisions. Public. A record that agents read on demand, not at start, and not a rule set: a decision that must bind every session is a line in AGENTS.md "Project rules". A project gets the blank copy from docs/templates/ instead. |
| docs/templates/ | Blank DECISIONS.md and LOG.md for a new project. Bootstrap moves them into docs/ and deletes this folder; sync uses the LOG.md copy. |
| .claude/skills/ | Claude Code skills, synced to projects. Each holds a procedure that only some tasks need, so its text loads only then; AGENTS.md names each file, so a host without skills can read it. `deliver` (commit, push, merge by lane A, B or C; the two check lanes; branch clean-up), `rule-change` (where a rule belongs, the Suggest format, what counts as approval, the caps), `personal-data` (the guard: state, a blocked push, the denylist), `data-change` (dry run, approval and counts for data writes and large queries), `verify` (start the app from the commands in AGENTS.md, prove a change by what it does, and measure a UI change with measure.mjs: screenshots at 375 and 1440 px, light and dark, contrast, target size, scroll), `handoff` (docs/NEXT_PROMPT.md, the resume prompt, start from a handoff) and `kit-update` (take a kit release by a sync pull request; where a project's own text goes). Full only: `delegate` (roles, Claude model by tier, fallbacks for claude.ai chat, briefs, review and merge), `audit` (the periodic bloat, drift, rule and speed audit), `efficiency` (a run slower than its baseline: confirm, find the cause, fix, record) and `project-log` (how to write a project log row). |
| docs/WORKING_WITH_AGENTS.md | For people new to agents: the working loop, clean context, how to ask, what to check. |
| docs/LOG.md | The kit's own public log (the owner, 2026-11-13). In a project (full only): the project log for a timeline and a story deck, from docs/templates/LOG.md: milestones, breakthroughs, misses and decisions, grouped into arcs. A public project keeps its log in a private place named in Project rules. |
| docs/host-prompts.md | Short pointer text for a claude.ai Project. |
| docs/FILES.md | This list. Kit only: bootstrap deletes it. |
| docs/reviews/ | Detailed evidence. Bootstrap deletes the kit's own reports, so a project starts with only docs/reviews/README.md. |
| docs/github/ | The owner's GitHub settings that an agent cannot set: two ruleset files to import on the default branch, and the secret-scanning steps. A project keeps them. |
| .check.state.json | Everything tools write (scripts/check_settings.py): the code standard's shrink-only debt list, the last audit and the timing baselines. Bootstrap replaces the kit's own state with a fresh file: the code standard adopted with no debt, no audit, no baselines. |
| PREFERENCES.md | The maintainer's current Claude account preferences as a template to fill in and paste, with the reason for each rule. Template repo only: bootstrap deletes it. |
| docs/account-skills/ | Account skills that PREFERENCES.md points to (the owner uploads them at claude.ai): `turn-summary`. Template repo only. |
| LICENSE | The kit's license (MIT). Bootstrap moves it to docs/archimedes_lever-LICENSE.txt; each project picks its own LICENSE. |
| .claude/settings.json | Claude Code deny list (force-push including --force-with-lease, `--no-verify`, changing core.hooksPath, hard reset, clean, stash, restore, `branch -D`, reading .env and key files), an allow list of the kit's own commands with an ask list (`--output`, `--record`), a sandbox with a network allowlist (GitHub, PyPI, npm), the Stop hook and the PreToolUse personal-data hook (`check_content.py --hook`) for outgoing tool calls. Applies to Claude Code only. |
| .claude/rule-tests.md | Full only. 20 scenarios that check whether an agent follows the written rules in AGENTS.md (hooks check the rest). Run a scenario after a change to its rule; all after a new Claude model family. Its "Section" column tells the rule lint which AGENTS.md sections have a scenario. |
| scripts/bloat_check.py | Full only. Quick measurements at each check-in: start-up reading size in tokens, rule counts against their caps, duplicate lines, big files, audit due date. `--skills` (run by check.sh) checks each skill's frontmatter and trigger text. `--rules` (run by check.sh) fails when a rule cap is passed or AGENTS.md names a path that does not exist, lists each rule line added or removed against origin/main, lints those lines, and with `--gate` (the full lane) fails until a fresh-context conflict check of them is recorded in docs/reviews/. `--lint` lints every rule (near-duplicate, vague, untested). `--time` runs timed operations and `--compare` takes times that a script measured; both compare with the baseline (warn only). Settings: the `audit-` lines of `.check`; state: `.check.state.json`. `--test`. |
| .claude/agents/ | Claude Code roles: `reviewer` (the author's tier, read-only); full only: `scout` (fast tier, read-only), `worker` (standard). |
| .github/workflows/check.yml | Pull-request and manual check, shown on GitHub as "checks": `scripts/check.sh`, then the guard on all files and the pull request's commits. A private repo skips the pull-request run (the owner, 2026-11-18); a manual run works everywhere. Never runs on push (to save Actions minutes). |
| .check | Every setting a person edits. The content check: the file turns on the scan of pushes and, in a public repo, of pull requests, and lists allowed exact strings, `skip:` paths and `block:` paths. The code standard and the audit: the `code-` and `audit-` lines (caps, scope, budgets; the keys: the header of scripts/check_settings.py). |
| scripts/check_settings.py | The one reader of the `code-` and `audit-` lines of `.check` and the one reader and writer of `.check.state.json`; an unknown key or a value that is not valid fails the check that reads it. `--migrate` moves the settings files of the layout before 2026-11-18 into the new files (docs/CHANGELOG.md). `--test`. |
| docs/FIRST_USE.md | The first-use questions and what the agent does with the answers. |
| scripts/first_use_check.py | Session-start check (Claude Code SessionStart hook): says KIT in the kit itself (a plain clone), FIRST USE when placeholders remain, DENYLIST when the guard is on and the session has no name list, and only RESUMED (plus DENYLIST) when the hook source is resume or compact. `--test`. |
| .gitignore | Keeps .env files and CLAUDE.local.md out of git. |
| scripts/check.sh | The one check command (AGENTS.md "Commands": Test), in two lanes: full (everything) and `--fast` (self-tests only of changed scripts; `check.local.sh --fast`). Checks run in parallel; a `TIME` line gives the wall time and the 3 slowest checks, and the next line compares the times with their baselines (`--record` stores new ones). Runs `scripts/check.local.sh` if it exists; otherwise prints SKIP for project checks. |
| docs/code-standard.md | The code standard: one-line comment per function, functions ≤ 60 lines, files ≤ 600 lines, lean code; which rules the check enforces and which the reviewer checks. |
| scripts/code_standard.py | The code standard check (run by check.sh in both lanes): measures every tracked source file and fails on debt not in `.check.state.json` (`--report`, `--update`, `--init`); caps and scope: the `code-` lines of `.check`. `--test` (cases in scripts/code_standard_test.py). Its parts: scripts/code_standard_parse.py (headers and function finders) and scripts/code_standard_docs.py (the opt-in full docs rule). |
| scripts/session_checkin.sh | Start and end check: branch, ahead/behind, uncommitted files, rule counts, and the time and slowest checks of the last check run; compares its own time with its baseline. Installs scripts/git-hooks as an absolute path (so a push from another folder finds the hook) when no other hooks path is set, and repairs the old relative path or a moved clone. `--test`. |
| scripts/git-hooks/pre-push | For Claude, any git client and people: blocks force-pushes, non-fast-forward pushes, deleting main or master, and a push that git runs outside the repo's own work tree (`git --git-dir=... push` from another folder); runs scripts/check.sh (the full lane for a push to main or master, the fast lane for other branches), and check_content.py on the tracked files and the pushed commits when `.check` exists. `--test`. |
| scripts/check_content.py | Personal-data and secret guard (`--all`, `--range A..B`, `--push`, files (a path it cannot read fails), `--stdin`, `--hook` (Claude Code PreToolUse: outgoing tool calls); `--require-denylist`; `--status`). `--test`. |
| scripts/check_content_scan.py, check_content_finders.py, check_content_hook.py, check_content_test.py, check_content_test_blocks.py, check_content_test_local.py | Parts of check_content.py (code standard C4): the settings and scans, the patterns and finders, the PreToolUse hook, the self-test cases. Always copied with it. |
| scripts/check_content_local.py, scripts/code_standard_gate.py | Not in the kit: a project's own extension files, which a sync never touches. The first replaces or adds finders of the content check (interface: the header of scripts/check_content_scan.py); the second adds stricter code-standard rules (interface: the header of scripts/code_standard.py). A file that cannot be loaded fails its check; `scripts/check.sh` runs each file's `--test` when it has one. |
| scripts/bloat_check_rules.py, bloat_check_skills.py, bloat_check_test.py | Parts of bloat_check.py: the rule census (`--rules`, `--lint`), `--skills` and the self-test cases. Full only, copied with it. |
| scripts/token_log_test.py | Self-test cases of token_log.py. Kit only. |
| scripts/stop_check.py | Claude Code Stop hook: stops a turn from ending while work is uncommitted or unpushed. `--test`. |
| scripts/token_log.py | Kit only. Claude Code Stop hook that the cloud setup scripts install from main: in the background, merges one row per API call (by message id, with its turn; subagents included) into `sessions/<session>.csv` on the branch `claude/token-usage` and pushes it, without touching the work tree. Repos only. `--push`, `--test`. |
| scripts/worker_guard.py | PreToolUse hook that limits what `worker` and `reviewer` may do in git. `--test`. |
| scripts/log_check.py | Full only. Checks docs/LOG.md against the project log rules. `--test`. |
| scripts/timeline.py | Full only. Turns one or more project logs into a single self-contained HTML timeline, or a Markdown story outline per arc for a deck (`--outline FILE`). `--test`. |
| scripts/drift.py | Kit only. Reports how a project differs from this kit; changes nothing. `--project DIR`, `--owner NAME`, `--test`. |
| scripts/sync_baseline.py | Kit only. Brings an existing project up to the current kit. Dry run by default; `--apply` writes. Keeps Project rules, Commands and docs/. A file a project may tune (the agents, docs/FIRST_USE.md) is replaced only when the project's copy is an earlier kit version; a tuned copy is kept and named. `--tier full` adds the advanced parts to a starter project. Holds the `ADVANCED_FILES` list. Its merges of project files (settings.json, .gitignore, the log's Arcs table): scripts/sync_merge.py. |
| scripts/bootstrap.sh | Fills in the placeholders once, then deletes itself. |
