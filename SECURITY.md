# Security policy

## Report a vulnerability

Do not write the details of a security problem in a public issue. Write no secret, token or personal data in a report or an issue.

Private reporting on GitHub is not on in every repository. The tab **Security** tells you which procedure to use.

1. On GitHub, open the main page of this repository. You see the row of tabs. Go on.
2. Click the tab **Security**. You see the page **Security overview**. Go on.

### If the page Security overview shows the button Report a vulnerability

1. On the page **Security overview**, click **Report a vulnerability**. You see the form **Report a vulnerability**. Go on.
2. In the form, type a title. Describe the problem, the files it touches and the steps that show it. You see your text in the form. Go on.
3. Click **Submit report**. You see your report in the list. The task is complete.

### If the page Security overview does not show the button Report a vulnerability

1. Click the tab **Issues**. You see the page **Issues**. Go on.
2. On the page **Issues**, click **New issue**. You see the form for a new issue. Go on.
3. In the title box, type `Security contact` only. You see the title in the form. Go on.
4. Click **Create**. You see your issue. Wait until the Maintainer answers in the issue with a private way to send the details. The task is complete.

## What happens next

The Maintainer reads each report and answers in the report, or in the private way that the Maintainer gave you. The Maintainer tells you if the problem is real and which version has the fix. The Maintainer does not publish the report until a fix is available.

## Scope

This policy covers the scripts, hooks and workflows in this repository. The file docs/threat-model.md lists the assets and the known risks.
